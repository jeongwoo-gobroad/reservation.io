# rev_004 판매 일자 오픈/마감과 Vercel Redis 동기화

## 목적

rev_003에서는 Vercel Redis waiting room key 구조를 정의했지만, 백엔드가 판매 일자를 열고 닫을 때 Vercel Redis에 `wr:open:{sale_date}`를 누가 쓰는지 명확하지 않았습니다.

이번 rev_004의 기준은 다음입니다.

```text
어드민 화면
→ Vercel Function
→ Cloud Run /admin/schedule-dates/{sale_date}/open 또는 /close
→ Cloud Run이 waiting_room_sync payload 반환
→ Vercel Function이 Redis wr:open:{sale_date} 갱신
→ 어드민 화면에 성공/경고 표시
```

백엔드는 Vercel Redis를 직접 호출하지 않습니다. Redis 연결 정보는 Vercel 프로젝트 안에만 두고, Cloud Run은 "어떤 key를 어떤 상태로 맞춰야 하는지"만 응답합니다.

## 백엔드 변경 사항

### 변경된 API

#### POST `/admin/schedule-dates/{sale_date}/open`

기존에는 일정 목록 배열을 바로 반환했습니다. 이제는 다음 객체를 반환합니다.

```json
{
  "sale_date": "2026-07-01",
  "schedules": [
    {
      "uuid": "schedule-set-uuid",
      "sale_date": "2026-07-01",
      "title": "1차 예약",
      "can_bundle": true,
      "has_time_slots": true,
      "reservation_open": true,
      "products": [],
      "time_slots": []
    }
  ],
  "waiting_room_sync": {
    "sale_date": "2026-07-01",
    "redis_key": "wr:open:2026-07-01",
    "desired_open": true,
    "redis_value": "1",
    "delete_key": false,
    "event": "schedule_date_opened",
    "message": "Vercel Redis에서 이 날짜 waiting room을 열어 주세요."
  }
}
```

#### POST `/admin/schedule-dates/{sale_date}/close`

응답 구조는 동일하지만 `waiting_room_sync`는 닫힘을 의미합니다.

```json
{
  "sale_date": "2026-07-01",
  "schedules": [],
  "waiting_room_sync": {
    "sale_date": "2026-07-01",
    "redis_key": "wr:open:2026-07-01",
    "desired_open": false,
    "redis_value": "0",
    "delete_key": true,
    "event": "schedule_date_closed",
    "message": "Vercel Redis에서 이 날짜 waiting room을 닫아 주세요."
  }
}
```

### 특수 케이스

어드민이 등록된 일정이 없는 날짜를 열면 백엔드는 `schedules=[]`와 함께 `desired_open=false`, `delete_key=true`를 반환합니다.

이 경우 Vercel은 waiting room을 열면 안 됩니다. 어드민 화면에는 "해당 날짜에 등록된 판매 일정이 없어 대기실을 열지 않았습니다"와 같은 안내를 보여주는 것이 좋습니다.

## 프론트엔드/Vercel이 해야 할 일

### 1. 어드민 오픈/마감 호출을 Vercel Function으로 감싸기

어드민 화면에서 Cloud Run을 직접 호출하지 말고, 아래처럼 Vercel Function을 거치십시오.

```text
POST /api/admin/schedule-dates/{sale_date}/open
POST /api/admin/schedule-dates/{sale_date}/close
```

Vercel Function 내부 흐름:

1. 어드민 Authorization 헤더를 읽습니다.
2. Cloud Run의 같은 관리자 API를 호출합니다.
3. Cloud Run 응답이 2xx가 아니면 Redis를 건드리지 않고 그대로 에러를 반환합니다.
4. Cloud Run 응답의 `waiting_room_sync`를 읽습니다.
5. `desired_open=true`이면 Redis에 `redis_key`를 `redis_value`로 저장합니다.
6. `delete_key=true`이면 Redis에서 `redis_key`를 삭제합니다.
7. Redis 갱신이 성공하면 Cloud Run 응답에 `waiting_room_synced=true` 같은 프론트 전용 값을 덧붙여 반환해도 됩니다.

### 2. Redis 쓰기 규칙

권장 규칙:

```text
desired_open=true:
  SET wr:open:{sale_date} 1

delete_key=true:
  DEL wr:open:{sale_date}
```

`desired_open=false`일 때 `SET key 0`을 해도 되지만, waiting room 판단 로직이 단순해지도록 `DEL`을 권장합니다.

### 3. Redis 갱신 실패 처리

Cloud Run 일정 오픈/마감은 성공했지만 Redis 갱신이 실패할 수 있습니다.

이 경우 어드민 화면에는 다음처럼 명확히 보여주십시오.

```text
판매 일정 상태는 저장되었습니다.
하지만 Vercel 대기실 상태 동기화에 실패했습니다.
잠시 뒤 다시 "해당 일자 오픈/마감" 버튼을 눌러 동기화해 주세요.
```

같은 오픈/마감 API를 다시 호출해도 백엔드 상태는 같은 값으로 맞춰지므로 재시도해도 됩니다.

### 4. 예약 생성/수정/취소 waiting room과 연결

예약 생성/수정/취소 Vercel Function은 요청의 `sale_date`를 기준으로 Redis를 확인합니다.

```text
wr:open:{sale_date} == 1
  waiting room 활성
  queue/lease 확인 후 Cloud Run 호출

wr:open:{sale_date} 없음
  waiting room 비활성
  운영 정책에 따라 바로 Cloud Run 호출 또는 예약 불가 안내
```

예약 수정/취소에서는 요청 본문에 `sale_date`가 없을 수 있습니다. 이 경우 프론트가 보유한 예약 정보의 `sale_date`를 Vercel Function에 함께 보내거나, Function이 먼저 내 예약 조회 결과를 참고해야 합니다.

### 5. 관리자 화면 표시

어드민이 판매 일자를 열거나 닫은 뒤에는 아래 두 상태를 모두 보여주는 것이 좋습니다.

- 백엔드 일정 상태: 오픈/마감 저장 성공 여부
- Vercel 대기실 상태: Redis `wr:open:{sale_date}` 동기화 성공 여부

문구 예시:

```text
판매 일자 2026-07-01을 예약 가능 상태로 저장했습니다.
Vercel 대기실도 열렸습니다.
```

```text
판매 일자 2026-07-01을 예약 마감 상태로 저장했습니다.
Vercel 대기실도 닫혔습니다.
```

## 구현 시 주의사항

- `RESERVATION_GATEWAY_SECRET`과 Redis 토큰은 브라우저에 노출하지 않습니다.
- `BACKEND_API_BASE_URL`은 Vercel 서버 함수 내부에서만 사용합니다.
- Cloud Tasks worker 주소인 `RESERVATION_WORKER_URL`은 Vercel에 두지 않습니다.
- Redis 상태가 일시적으로 어긋나도 최종 예약 가능 여부는 Cloud Run worker가 SQL 기준으로 다시 검증합니다.
- Redis waiting room은 부하 완충 장치이고, 최종 정합성 장치는 SQL transaction입니다.

## 테스트 케이스

- 일정이 있는 날짜 open 후 응답의 `waiting_room_sync.redis_key`가 `wr:open:{sale_date}`인지 확인
- 일정이 있는 날짜 open 후 `desired_open=true`, `redis_value=1`, `delete_key=false`인지 확인
- close 후 `desired_open=false`, `delete_key=true`인지 확인
- 일정이 없는 날짜 open 후 `desired_open=false`, `delete_key=true`인지 확인
- Vercel Function에서 Cloud Run open 성공 후 Redis SET 성공 시 어드민 성공 메시지 표시
- Vercel Function에서 Cloud Run close 성공 후 Redis DEL 성공 시 어드민 성공 메시지 표시
- Redis 쓰기 실패 시 어드민에게 부분 성공/동기화 실패 메시지 표시
- 예약 생성/수정/취소 Function이 `wr:open:{sale_date}`를 기준으로 waiting room을 적용하는지 확인
