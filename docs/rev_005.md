# rev_005 개인정보 관리, 숫자 숨김, 지난 일정 조회

이번 변경은 프론트엔드가 새 화면을 구현할 때 필요한 API 계약과 화면 동작을 정리합니다.

## 변경 요약

- 이용자 개인정보 수정 화면을 지원합니다.
- 이용자 회원 탈퇴 API를 추가했습니다.
- 개인정보 처리방침을 `/static/personal.md`에서 마크다운으로 제공합니다.
- 관리자 예약 현황 응답에 고객명 필드를 추가했습니다.
- 일정별로 이용자 화면에 재고 숫자와 방문 시간 인원 숫자를 숨길 수 있습니다.
- 관리자 일정 목록은 기본적으로 오늘 이후 일정만 보여주고, 지난 일정은 별도 페이지형 API로 조회합니다.

## 이용자 개인정보 화면

프론트엔드에 “개인정보 관리” 또는 “내 정보” 페이지를 둡니다.

필수 구성:

- 현재 닉네임 표시
- 닉네임 변경 입력칸
- 닉네임 저장 버튼
- 회원 탈퇴 버튼

사용 API:

- `GET /users/me`
- `PATCH /users/me/nickname`
- `DELETE /users/me`

닉네임 변경:

```http
PATCH /users/me/nickname
Authorization: Bearer <user-token>
Content-Type: application/json
```

```json
{
  "nickname": "피카츄트레이너"
}
```

회원 탈퇴:

```http
DELETE /users/me
Authorization: Bearer <user-token>
```

성공 시 `204 No Content`입니다.

프론트 처리:

- 탈퇴 버튼을 누르면 바로 호출하지 말고 확인 창을 보여줍니다.
- 확인 문구에는 “계정, 예약, 방문 확인, 노쇼, 예약 제한 기록이 삭제되며 복구할 수 없습니다”를 포함합니다.
- 성공 후 로컬 저장소의 사용자 토큰을 삭제하고 로그인 화면으로 이동합니다.
- 기존 토큰으로 API를 호출하면 401이 날 수 있으므로, 401 응답은 로그인 만료 또는 탈퇴 상태로 처리합니다.

## 개인정보 처리방침 페이지

사용 API:

```http
GET /static/personal.md
```

응답은 마크다운 원문입니다.

프론트 처리:

- 별도 개인정보 처리방침 페이지에서 Markdown 렌더러로 표시합니다.
- 로그인 전에도 접근 가능하게 두는 것이 좋습니다.
- 푸터 또는 회원가입/로그인 화면에서 이 페이지로 이동할 수 있게 합니다.

## 관리자 예약 현황 고객명 수정

기존에는 `GET /admin/reservations` 응답에 고객명이 없어 화면에 `-`가 표시될 수 있었습니다.

변경 후 각 예약 항목에는 다음 필드가 포함됩니다.

```json
{
  "user_uuid": "user-uuid",
  "nickname": "피카츄트레이너",
  "customer_name": "피카츄트레이너"
}
```

프론트 처리:

- 고객명 열에는 `customer_name`을 우선 표시합니다.
- `customer_name`이 비어 있으면 `nickname`을 표시합니다.
- 둘 다 비어 있으면 `-`를 표시합니다.

## 이용자 재고/인원 숫자 숨김

관리자는 판매 일정 생성 또는 수정 시 다음 값을 설정할 수 있습니다.

```json
{
  "show_stock_remaining": true,
  "show_time_slot_remaining": true
}
```

의미:

- `show_stock_remaining=false`: 이용자에게 재고 관련 숫자를 숨깁니다.
- `show_time_slot_remaining=false`: 이용자에게 방문 시간별 인원 숫자를 숨깁니다.

이용자용 `GET /schedules/open` 응답:

- 재고 숨김이면 `products[].stock_quantity`와 `products[].stock_remaining`이 `null`입니다.
- 방문 인원 숨김이면 `time_slots[].capacity`와 `time_slots[].remaining_customers`가 `null`입니다.
- 관리자용 일정 API는 실제 숫자를 계속 반환합니다.

프론트 처리:

- 값이 `null`이면 숫자 영역 자체를 숨깁니다.
- `-1` 같은 특수 숫자를 기대하지 않습니다.
- 숫자가 숨겨져 있어도 예약 버튼은 표시할 수 있습니다.
- 최종 예약 가능 여부는 예약 요청 결과의 성공/실패로 판단합니다.

권장 문구:

- 재고 숨김: “예약 가능 여부는 신청 후 확인됩니다.”
- 방문 인원 숨김: 시간 선택 버튼에는 시간만 표시합니다.

## 관리자 일정 조회

기본 일정 목록:

```http
GET /admin/schedules
Authorization: Bearer <admin-token>
```

오늘 이후의 일정만 반환합니다.

지난 일정 목록:

```http
GET /admin/schedules/past?offset=0&limit=20
Authorization: Bearer <admin-token>
```

응답:

```json
{
  "items": [],
  "total": 42,
  "offset": 0,
  "limit": 20,
  "has_more": true
}
```

프론트 처리:

- 일정 관리 기본 화면에는 `GET /admin/schedules`만 사용합니다.
- “지난 일정 보기” 페이지 또는 탭을 별도로 둡니다.
- 지난 일정 화면에는 `limit` 선택 또는 “더 보기” 버튼을 둡니다.
- `has_more=true`이면 다음 페이지를 더 불러올 수 있습니다.

권장 limit:

- 10
- 20
- 50

## 관리자 일정 생성/수정 화면

일정 생성 화면에 다음 체크박스를 추가합니다.

- 이용자에게 남은 재고 수 보여주기
- 이용자에게 방문 시간별 남은 인원 보여주기

기본값은 둘 다 켜짐입니다.

컴퓨터 비전공자 관리자를 위한 화면 문구:

- “남은 재고 숫자를 손님에게 보여주기”
- “방문 시간별 남은 자리 수를 손님에게 보여주기”

피해야 할 문구:

- `show_stock_remaining`
- `null`
- `capacity`
- `API`
- `DB`

## 백엔드 정합성 메모

- 숫자를 숨기는 기능은 화면 표시만 바꿉니다.
- 재고 부족, 방문 시간 마감, 1인당 구매 제한 검사는 예약 worker의 트랜잭션에서 그대로 수행됩니다.
- 고객명이 필요한 관리자 예약 현황은 예약과 사용자 관계를 함께 조회합니다.
- 회원 탈퇴는 탈퇴 표시가 아니라 물리 삭제입니다.
- 삭제 범위는 `users`, `reservations`, `reservation_requests`, `completed_visits`, `no_show_counts`, `banned_users`입니다.
- 수동 방문 코드 저장소가 memory 또는 Firestore이면 `user_uuid`로 남은 수동 코드도 삭제합니다.
- 회원 탈퇴와 예약 worker는 같은 잠금 순서를 사용하도록 맞췄습니다. 삭제 중인 사용자의 남아 있는 예약 요청은 삭제 대상에 포함됩니다.
- 법령상 개인 식별 정보 삭제가 우선이므로, 탈퇴 후 관리자 예약 현황과 최근 방문 확인 내역에서도 해당 고객의 개인 기록은 조회되지 않습니다.
