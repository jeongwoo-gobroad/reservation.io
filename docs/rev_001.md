# rev_001 변경 명세

이 문서는 예약 수정, 상단 닉네임 표시, 고유 일정 재예약 제한, 프론트 1차 반복 클릭 방어에 대한 변경점을 정리합니다.

> 현재 백엔드는 IP 기반 자동 밴, 관리자 로그인 실패 기반 IP 밴, DB 기반 요청 카운팅을 수행하지 않습니다. 반복 요청 차단은 Vercel Rewrites + Vercel KV 같은 프론트/프록시 계층에서 처리하는 방향으로 정리되었습니다. 관련 최신 내용은 `docs/rev_002.md`를 기준으로 삼으십시오.

## 핵심 변경 요약

- 고객 화면 상단바에 닉네임을 표시합니다.
- 같은 고객이 한 번 수령 완료 또는 노쇼 처리된 동일 판매 일정은 다시 예약할 수 없습니다.
- 고객은 재고, 1인당 제한, 상품 그룹 제한, 방문 시간 정원 안에서 기존 예약의 수량과 방문 시간을 수정할 수 있습니다.
- 프론트엔드는 예약, 예약 수정, 예약 취소, 방문 확인, 영업 마감 같은 버튼을 누른 직후 비활성화하여 중복 요청을 줄여야 합니다.

## 고객 닉네임 표시

사용 API:

- `GET /users/me`

응답의 `nickname`을 고객 화면 상단바에 간단히 표시합니다.

권장 표시:

- 닉네임이 있으면 그대로 표시합니다.
- 닉네임이 비어 있으면 닉네임 설정 화면으로 안내합니다.
- 운영 화면에는 디버그용 사용자 식별 코드를 노출하지 않습니다.

## 고유 일정 재예약 제한

백엔드는 같은 사용자와 같은 `schedule_set_uuid` 조합에 대해 이미 `visited` 또는 `no_show` 상태 예약이 있으면 새 예약을 거절합니다.

예외:

- `cancelled` 상태는 재예약을 허용합니다.
- 아직 `reserved` 상태인 예약은 기존의 같은 날짜 중복 예약 제한 규칙을 따릅니다.

프론트엔드 작업:

- 예약 실패 시 백엔드의 `detail` 메시지를 그대로 고객에게 보여줍니다.
- 수령 완료 또는 노쇼 처리된 일정이 예약 가능 목록에 보이더라도 최종 예약 버튼에서 실패할 수 있으므로, 고객에게 “이미 수령 또는 노쇼 처리된 일정은 다시 예약할 수 없습니다”라는 표현을 준비합니다.

## 예약 수정 API

### PATCH `/reservations/{reservation_uuid}`

고객이 본인 예약의 수량 또는 방문 시간을 수정합니다.

인증:

- 사용자 Bearer 토큰 필요

요청:

```json
{
  "quantity": 2,
  "time_slot_uuid": "time-slot-uuid"
}
```

부분 수정:

- `quantity`만 보낼 수 있습니다.
- `time_slot_uuid`만 보낼 수 있습니다.
- 둘 다 보낼 수 있습니다.

응답:

```json
{
  "uuid": "reservation-uuid",
  "sale_date": "2026-07-01",
  "schedule_set_uuid": "schedule-set-uuid",
  "schedule_title": "1차 예약",
  "product_uuid": "product-uuid",
  "product_name": "상품명",
  "quantity": 2,
  "time_slot_uuid": "time-slot-uuid",
  "time_slot_label": "14:30",
  "status": "reserved",
  "reserved_at": "2026-06-20T01:00:00Z"
}
```

백엔드 검증:

- 현재 로그인한 사용자의 예약인지 확인합니다.
- 예약 상태가 `reserved`일 때만 수정합니다.
- 상품 재고를 넘지 않는지 확인합니다.
- 상품별 1인당 최대 구매 개수를 넘지 않는지 확인합니다.
- 상품 그룹 구매 제한을 넘지 않는지 확인합니다.
- 방문 시간 정원이 남아 있는지 확인합니다.

프론트엔드 작업:

- 내 예약 카드에 “예약 수정” 버튼을 둡니다.
- 수정 화면에는 현재 수량과 현재 방문 시간을 기본값으로 넣습니다.
- 수량 선택 UI는 1부터 상품별 `per_user_limit`까지 보여줍니다.
- 방문 시간 선택 UI는 같은 일정의 `time_slots`를 실제 시간 라벨로 보여줍니다.
- 저장 중에는 버튼을 비활성화합니다.
- 성공하면 내 예약 목록을 다시 불러옵니다.
- 실패하면 백엔드 메시지를 화면에 그대로 표시합니다.

## 시간 표시

- 예약 카드 본문에는 `Seoul, KR` 같은 지역명을 반복해서 넣지 않습니다.
- 화면 맨 아래 footer에만 `시간 표시 기준: Seoul, KR`을 표시합니다.
- 예약 일시는 고객이 이해하기 쉬운 로컬 시간 문자열로 표시합니다.
- 방문 시간은 `14:00`처럼 실제 시간만 보여줍니다.

## 프론트 1차 반복 클릭 방어

백엔드는 현재 IP 기반 요청 차단을 하지 않습니다. 프론트엔드는 고객 실수로 같은 요청이 여러 번 전송되지 않도록 다음 처리를 해야 합니다.

- 예약하기, 예약 수정, 예약 취소, 방문 완료, 영업 마감 버튼은 클릭 직후 비활성화합니다.
- 요청이 끝나기 전 같은 버튼을 다시 누를 수 없게 합니다.
- 같은 API를 짧은 시간에 반복 호출하는 화면은 300-500ms debounce 또는 throttle을 둡니다.
- QR 갱신은 `expires_in_seconds` 기준으로 방문 확인증 화면이 열려 있을 때만 호출합니다.

## 관리자 화면 반영 목록

관리자 메인:

- 마감하지 않은 지난 영업일을 계속 표시합니다.
- 영업 마감 시 “오지 않은 고객은 노쇼 처리됩니다”라는 확인 창을 보여줍니다.

문구 관리:

- 로그인 안내문과 예약 동의 메시지를 관리합니다.

일정 관리:

- 상품 입력에는 전체 재고와 1인당 최대 구매 제한을 모두 보여줍니다.
- 상품 그룹 구매 제한을 명확히 표시합니다.

방문 확인:

- 방문 완료된 예약은 같은 고유 일정에서 다시 예약할 수 없음을 운영자에게 안내할 수 있어야 합니다.
