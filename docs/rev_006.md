# rev_006 일정 삭제 무결성 보강

## 발생한 문제

관리자 일정 삭제 중 다음 오류가 발생할 수 있었습니다.

```text
null value in column "product_id" of relation "reservations" violates not-null constraint
```

원인은 일정이 삭제되면서 연결된 상품도 함께 삭제되고, SQLAlchemy가 해당 상품을 바라보던 예약의 `product_id`를 `NULL`로 바꾸려 했기 때문입니다. 하지만 `reservations.product_id`는 필수값이라 DB가 이를 거부했습니다.

## 변경된 처리 방식

`DELETE /admin/schedules/{schedule_set_uuid}`는 이제 일정 본체를 삭제하기 전에 연결 기록을 먼저 정리합니다.

삭제 순서:

1. 해당 일정의 예약을 잠급니다.
2. 해당 예약과 연결된 방문 확인 기록을 삭제합니다.
3. 해당 일정 또는 예약과 연결된 예약 요청 기록을 삭제합니다.
4. 해당 일정의 예약을 삭제합니다.
5. 일정, 상품 그룹, 상품, 방문 시간을 삭제합니다.

이 순서를 지키면 예약 행의 `product_id`를 `NULL`로 바꾸는 상황이 생기지 않습니다.

## 앞으로 DB 구조를 바꿀 때 지켜야 할 원칙

새 테이블이 다음 중 하나를 저장한다면 삭제 정책에 반드시 포함해야 합니다.

- `reservation_id`
- `reservation_uuid`
- `schedule_set_id`
- `schedule_set_uuid`
- `product_id`
- `product_uuid`
- `time_slot_id`
- `user_id`
- `user_uuid`
- 고객 닉네임처럼 개인을 식별할 수 있는 값

일정 삭제와 관련된 테이블은 `reservation_api.main.delete_schedule_dependents()`에 추가합니다.

회원 탈퇴와 관련된 테이블은 `DELETE /users/me` 내부 삭제 순서에 추가합니다.

## 프론트엔드 영향

프론트 API 호출 방식은 바뀌지 않습니다.

다만 일정 삭제는 연결된 예약과 방문 확인 기록까지 삭제되는 강한 작업입니다. 관리자 화면에서는 삭제 전 확인 창에 다음 내용을 보여주십시오.

> 이 일정을 삭제하면 연결된 예약과 방문 확인 기록도 함께 삭제되며 복구할 수 없습니다.

## 검증 케이스

다음 케이스를 재현해 통과를 확인했습니다.

- 취소된 예약이 남아 있는 일정 삭제
- 방문 확인 기록이 남아 있는 일정 삭제
- 예약 요청 기록이 남아 있는 일정 삭제
- 삭제 후 일정, 상품, 방문 시간, 예약, 방문 확인, 예약 요청 기록이 모두 삭제되는지 확인
